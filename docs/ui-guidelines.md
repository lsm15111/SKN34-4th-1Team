# 화면·문구 통일 기준

웹(`frontend/web`)과 모바일(`frontend/mobile`)이 같은 기능을 같은 말과 같은 모양으로 보여 주기 위한 기준입니다.
새 화면을 만들거나 기존 화면을 고칠 때 이 문서를 따르고, 기준을 바꿀 때는 이 문서를 먼저 고칩니다.
범정부 디자인 시스템(KRDS)의 토큰 구조·접근성 규칙과 토스 UX 라이팅 원칙을 참고했지만, GovBiz 브랜드(초록)와
기존 화면의 값을 기준으로 삼습니다. KRDS의 정부 식별 요소(공식 배너·운영기관 식별자)는 쓰지 않습니다.

## 1. 말투와 문장

- 화면 문구는 **해요체**로 씁니다. 버튼·라벨·안내·빈 화면·오류·알림이 모두 대상입니다.
- 합니다체는 약관·개인정보 처리방침·동의 문구처럼 법적 문서이거나, 신청서처럼 공식 문서에 들어가는 내용에만 씁니다.
- 띄어쓰기: "해 주세요", "알려 주세요", "확인해 주세요"(보조용언 띄어 씀).
- 한 문장에 한 가지만 말합니다. 안내는 한 문장을 넘기지 않고, 더 필요한 내용은 "자세히"나 도움말로 보냅니다.
- 능동형으로 씁니다("저장됐어요" 대신 "저장했어요"). 개발자 설명("~로 대신 표시하지 않습니다")을 사용자에게 보이지 않습니다.
- 같은 안내를 한 화면에서 반복하지 않습니다. 특히 "원문에서 확인해 주세요"류의 주의 문구는 화면당 한 번만 둡니다.

## 2. 버튼 문구

| 상황 | 문구 |
|---|---|
| 화면의 주된 행동 하나 | 동사로 끝냄: "검토 실행", "문서 만들기", "저장하기" |
| 대화상자 닫기 | "닫기" (취소할 작업이 없는 경우) |
| 진행 중인 작업 멈추기 | "중단하기" |
| 입력 중인 변경 버리기 | "취소" |
| 되돌릴 수 없는 작업 확인 | 결과를 말하는 동사: "삭제하기", "탈퇴하기" |
| 실패 뒤 재시도 | "다시 시도" |

## 3. 같은 대상은 같은 이름

| 대상 | 쓰는 이름 | 쓰지 않는 이름 |
|---|---|---|
| 공고 상태 OPEN / UPCOMING / CLOSED / UNKNOWN | 접수 중 / 접수 예정 / 접수 마감 / 상태 확인 필요 | 접수 종료, 마감, 상태 미확인 |
| 마감까지 남은 날 | D-3, D-day (마감일 당일) | D-Day, D-0 |
| 진행 단계 | 준비 중 / 제출 완료 / 서류 심사 / 발표 심사 / 선정 / 미선정 | 지원 완료, 탈락 |
| 사용자가 담은 공고 | 담은 공고 | 저장된 공고(DB에 있다는 뜻과 헷갈림) |
| 날짜 | 2026.10.02 (올해가 아니면 연도 포함, 올해면 10.02도 가능) | 2026년 10월 2일 오후 9:51 |
| 공고 저장 | 관심 공고에 담기 / 관심 공고에서 빼기 | 저장, 추가 |
| 검색 방식 | AI 검색 / 필터 검색 | AI 대화 검색, 공고 검색 |
| 새 검색 시작 | 새 검색 | 새검색, 새 대화 |
| 신청 문서 메뉴 / 새로 만들기 | 신청 문서 작성 / 새 신청 문서 | 새 신청문서, 새 문서 |
| 중복 검토 메뉴(좁은 곳) | 중복 지원·수혜 검토(중복 검토) | — |
| 맞춤 리포트 | 맞춤 리포트 | 기업 맞춤 리포트(메뉴), 리포트 |
| 계정 화면 | 내 정보 | 내 프로필, 내 계정, 기업 프로필 |

상태·단계·라벨의 표시 문구는 `frontend/packages/shared`의 한 곳에서 정의하고 웹과 모바일이 함께 가져다 씁니다.

## 4. 색과 토큰

- 색·모서리·간격 값은 `frontend/packages/shared/src/design/tokens.ts` 한 곳에 둡니다. 웹은 이 값으로 만든 Tailwind
  `@theme` 변수를, 모바일은 같은 파일의 값을 씁니다. 화면 코드에 16진수 색을 직접 쓰지 않습니다.
- 의미 이름을 씁니다: `brand-primary`, `brand-hover`, `brand-soft`, `surface`, `surface-muted`, `line`, `line-strong`,
  `ink`, `ink-muted`, `ink-subtle`, `danger`, `warning`, `info`(각 `-soft`, `-line`).
- `info`는 파란색 계열입니다. 초록은 브랜드·성공에만 씁니다.
- 글자색은 배경 대비 4.5:1 이상, 아이콘·테두리 같은 UI 요소는 3:1 이상을 지킵니다.

## 5. 페이지 구성

기준 화면은 `/app/combination-reviews`(목록)이고, 빈 화면은 `/app/application-preparations/new`의 형태를 따릅니다.

- **머리글:** 작업 화면은 항상 `WorkspacePageHeader`를 씁니다. 제목 하나(h1)와 필요하면 한 문장(60자 이내) 설명을 두고,
  사이드바·탭 이름과 제목을 같게 씁니다. 작업 화면 안에는 홍보용 큰 제목(hero)을 두지 않습니다. 브라우저 제목(`<title>`)도
  화면마다 "화면 이름 · GovBiz"로 바꿉니다.
- **너비:** 목록은 본문 폭 전체를, 입력 화면과 읽는 화면은 최대 880px를 씁니다.
- **카드:** 기본 카드 하나를 씁니다(태그 → 두 줄 제목 → 한 줄 설명 → 구분선 → 날짜와 행동). 점선 테두리는 빈 화면에만 씁니다.
- **단계 표시:** 여러 단계 입력(환영, 새 신청 문서, 새 검토, 모집글 작성)은 같은 단계 표시 하나를 씁니다.
- **도우미 버튼:** 채팅 화면에서는 숨기고, 아래쪽 고정 버튼이 있는 화면에서는 그 위로 올려 가리지 않게 합니다.
- **주된 행동:** 채운 버튼은 화면당 하나입니다. 데스크톱은 머리글 오른쪽, 모바일은 화면 아래에 둡니다.
- **불러오는 중:** 목록은 뼈대(skeleton)를 쓰고, 1초 이상 걸리는 작업에만 회전 표시를 씁니다. 로그인 확인 중에도 빈 화면을 두지 않습니다.
- **빈 화면:** 지금 상태 + 이유 + 다음 행동 버튼 하나("관심 공고가 없어요" + "공고 찾기").
- **오류:** 무엇이 왜 안 됐는지 + 할 일을 한 문장으로 쓰고 "다시 시도"를 둡니다. 입력한 내용은 지우지 않습니다.
- **목록 넘기기:** 사용자 목록은 "더 보기", 관리자 표는 번호 쪽 넘김을 씁니다.

## 6. AI 안내

- AI가 만든 내용에는 입력창 옆에 한 줄만 둡니다: "AI 안내예요. 신청 전에 공고 원문에서 자격과 기간을 확인해 주세요."
- 결과마다, 카드마다 면책 문구를 반복하지 않습니다. 조건이 확인되지 않은 카드에만 "확인 필요" 표시를 붙입니다.
- AI 답변은 결론을 첫 문장에 둡니다. 인사·칭찬·마무리 인사·과정 설명을 넣지 않습니다.
- 근거는 원문 문장을 그대로 짧게 인용하고, 링크는 모델이 쓰지 않고 화면이 출처 정보로 만듭니다.

## 7. 접근성과 줄바꿈

- 한글 단어가 음절 중간에서 끊기지 않도록 전역에 `word-break: keep-all; overflow-wrap: anywhere;`를 둡니다.
- 사용자에게 내부 용어(모델·비용·HTML 본문·입력 버전·실행 기록 등)를 보이지 않습니다. 운영자 화면에서만 씁니다.
- 아직 동작하지 않는 기능은 "준비 중" 버튼으로 두지 않고 화면에서 뺍니다.
- 누를 수 있는 요소는 44×44px 이상입니다.
- 키보드 초점이 보여야 하고, 상태가 바뀌는 안내는 `role="status"`로 읽어 줍니다.
- 색만으로 상태를 구분하지 않고 글자나 아이콘을 함께 씁니다.
